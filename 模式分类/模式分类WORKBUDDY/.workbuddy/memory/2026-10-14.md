## 为 WORKBUDDY 空间所有文件添加属性标记

**背景**：用户要求给 `E:\阅读资料\模式分类\WORKBUDDY`（Obsidian 仓库）中所有文件加"属性标记"，即 YAML frontmatter。

**做法**：新增 `WORKBUDDY\build_props.py`（幂等）。
- 14 个 .md 笔记全部写入 frontmatter：`title / aliases / type / tags / status / created / updated`，章节笔记另加 `chapter / book_pages / prev_chapter / next_chapter / upstream / downstream / chars`；总览加 `chapters / reading_routes`；附录加 `covers`；合订本加 `source`；首页加 `hub / notes_count / downstream`。
- 2 个 Python 脚本（build_doc.py / build_links.py）无法承载 YAML，改用文件头 `# ---- PROPS:BEGIN/END ----` 注释块声明同名字段。
- `upstream / downstream` 由**解析各章已有导航块**得出，不重复实现链接逻辑，保证属性与双向链接永远一致。
- README 增加「属性标记约定」小节（`<!-- PROPS:DOC:BEGIN/END -->` 标记，幂等）。

**踩坑**
- 前后章解析最初把"序列行里两个链接都赋给 prev"，已改为专用正则 `\[\[x\|←` / `\[\[x\|[^]]*→`。
- 首章/末章的 prev/next 为 None 时要**省略字段**，不能写字面量 `None`。
- **build_doc.py 会给合订本 md 重新拼接内容，会抹掉合订本自己的 frontmatter 与导航块**，所以正确执行顺序是：
  `build_doc.py` → `build_props.py` → `build_links.py`
- 因此给 build_doc.py 增加了"拼接前剥离各文件 frontmatter"的逻辑，否则 14 段 frontmatter 会被当成正文拼进合订本与 Word。

**校验**：14 篇 md + 2 个 py 全部带属性，177 个属性字段；Word 无 frontmatter / 导航块泄漏；80 条链接仍全部双向、无断链。
